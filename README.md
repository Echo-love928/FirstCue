# FirstCue · AI 热点情报台

收集网页搜索、X 和官方订阅中的新信息，使用 OpenRouter 核实事件、合并转载和生成中文摘要。关键词与领域范围统一每 30 分钟检查；只有基线之后新增且核实的关键词命中进入邮件队列。

## 本地运行

需要 Node.js **24.16.0–24.x**。项目使用该版本的 `node:sqlite`，不兼容旧版 Node。

```powershell
npm ci
# 首次使用时复制示例；已有 .env 时不要覆盖。
Copy-Item .env.example .env
npm run dev
```

开发页面：<http://127.0.0.1:5173/>。API：<http://127.0.0.1:3030/>。

构建后可直接运行，不需要 Vite：

```powershell
npm run build
npm start
```

正式本地页面：<http://127.0.0.1:3030/>。两种启动方式都包含 API 与独立后台 worker；使用一种即可。在终端按 Ctrl+C 停止。关闭网页不会停止后台，关闭进程或电脑休眠会暂停监控。

## 配置

密钥只保存在本地 `.env`；修改后重启。页面不收集或返回密钥。

| 环境变量 | 用途 |
| --- | --- |
| OPENROUTER_API_KEY | OpenRouter Key，需要可用额度 |
| OPENROUTER_MODEL | 默认 `deepseek/deepseek-v4.1-flash`，已核对支持结构化输出 |
| TWITTERAPI_IO_KEY | TwitterAPI.io Key 与可用额度 |
| SMTP_HOST / SMTP_PORT | 邮件服务器与端口 |
| SMTP_SECURE | 465 通常为 true；587 通常为 false，仍要求 STARTTLS |
| SMTP_USER / SMTP_PASS | SMTP 账号与授权码 |
| SMTP_FROM | 发件人地址 |
| NOTIFY_EMAIL | 初始接收邮箱，也可在页面设置 |
| FEISHU_WEBHOOK_URL | 飞书群自定义机器人的完整 Webhook 地址 |
| FEISHU_SIGNING_SECRET | 可选签名校验密钥，与飞书机器人安全设置保持一致 |
| HTTPS_PROXY / HTTP_PROXY | 可选出站 HTTP 代理；不得放入浏览器配置 |
| TRUSTED_X_IDS | 已核验官方身份的稳定 X 用户 ID，逗号分隔；蓝标和用户名不自动成为官方依据 |

模型、接收邮箱和调用限额保存到 SQLite 后，页面设置优先于初始环境默认值。当前服务仅接受本地回环访问；部署前需另行设计访问认证与网络配置。

### 飞书与邮箱同时通知

1. 在飞书目标群的「设置 → 群机器人」中添加「自定义机器人」，复制 Webhook 地址。建议在机器人的安全设置中开启「签名校验」，复制密钥并保存机器人设置。
2. 在现有 `.env` 中增加以下两项，保留 SMTP 和其他配置；不要把真实 Webhook 或密钥发送到聊天或提交到仓库：

   ```dotenv
   FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/替换为实际机器人ID
   FEISHU_SIGNING_SECRET=替换为签名校验密钥
   ```

   如果机器人没有启用签名校验，第二项留空。如果启用关键词校验，请允许 `FirstCue`，正式通知与测试消息均包含该标识。第一版仅支持飞书国内版的官方 `open.feishu.cn` Webhook。
3. 重启项目（开发模式 `npm run dev`，生产模式先 `npm run build` 再 `npm start`）。在「设置与连接 → 飞书群通知」勾选「启用飞书，与邮箱同时通知」，点击「保存设置」，再发送飞书测试消息，进入目标群确认实际收件。测试入口也允许在自动通知关闭时测试。
4. 「我的监控」中启用关键词监控的通知开关。之后新增且核实的命中会分别进入邮箱与飞书队列；邮箱继续使用原有接收地址，飞书启用前已经发现的热点不批量补发。
5. 「通知记录」可筛选邮箱或飞书，查看各自的状态和错误，单独重试失败通知。已接受的通知不主动重发；网络超时可能存在服务已接受但本机未收到响应的情况，因此不能保证端到端恰好送达一次。

关闭后重新启用飞书，或更换 Webhook 到另一个群，会重新建立渠道启用时间；旧队列不会投递到新群。飞书每个后台 tick 最多发送一条，失败按 2、4、8 分钟退避，最多尝试 4 次，两路互不阻塞。API 接受不等于用户已读，首次配置仍需实际收件测试。监控频率仍为每 30 分钟，电脑休眠或后台停止期间不能发送通知。

接入依据：[飞书自定义机器人官方指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

## 使用流程

1. 在“我的监控”添加关键词目标或范围。搜索查询可包含英文产品名，例如 `Claude new model release` 或 `AI coding agents`；AI 按完整目标判断，不把简单关键词命中视为真实发布。
2. 在“信息来源”查看或暂停来源、添加 RSS/Atom、添加 X 账号时间线。Bing、百度、搜狗无需 Key；遇到访问校验会记录失败并停止该路本轮查询，各开关以页面为准。B站公开搜索、微博公开链接参与独立发现；内置 OpenAI、Google、Hugging Face、Anthropic、Cursor、VS Code、Qwen、DeepSeek 的公开入口，各来源状态分别记录。
3. 首次检查建立历史基线；之后每 30 分钟执行，也可点击“立即检查”。网页搜索有缓存和限速，X 使用增量窗口与游标续查。
4. “最新信号”默认展示近 5 天各平台的合格线索与已核实新事件，待核实明确标注。Twitter 仅保留纯原创，并同时满足点赞 ≥10、转发 ≥5、浏览 ≥500、作者粉丝 ≥100，官方也不豁免。回复（含官方/原作者）、引用、纯转发、类型未知、空泛讨论和旧闻仅保留审计。蓝 V 在同一时效档内热度排序分加权 10%，不代表事实已核实；原创仍不强制外链。其他平台需要可读原始材料、作者或发布主体、近 5 天时间依据和实质新增事实。B站可依据视频简介作为待核实线索，卡片附视频链接；微博需要读取原帖。相同原文合并并展示发现渠道，更新时间不冒充发布时间。
5. AI 请求失败时保留候选；解决服务问题后点击“重新核实”，只复用已保存内容，不重复请求采集来源。连续未解决的候选不会无限重试。
6. 需要邮件时再填写 SMTP 与接收邮箱，先检查连接、发送测试邮件并确认收件，再验收自动通知。

Google / Hugging Face 等域名是否可访问取决于本机网络；失败有运行记录，不会被伪装为没有热点。Bing 搜索页可能出现校验或结构变化，此时停止该来源本轮请求。OpenRouter 返回 402 时先处理账号/Key 额度；“检查模型能力”只确认目录声明，不能代替真实推理。

## 数据、限额与验证

- 数据在 `data/signal.sqlite`，包括规则、候选、事件、检查点、通知和用量。备份时先停止进程，再复制整个 `data` 目录，保留 SQLite 的 WAL 文件。
- 默认每轮最多 10 次公开搜索（发现与补证共用）、30 条分析材料。合格主候选约 Twitter 70%、其他平台 30%，不足时由其他合格内容补足；补证不能占用预留给其他平台的材料额度。完整规则见 [多平台方案](docs/MULTIPLATFORM.md)。热点窗口固定为滚动 120 小时，超过 5 天自动隐藏并停止分析重试，原始与审计数据保留；新抓取、修改或转发不能刷新旧事件。X 每查询最多 3 页，有效窗口继续保留，过期窗口直接放弃。每日默认 AI 100 次、X 200 次请求 / 2000 条结果，可在设置调整。
- AI 每批 15 条，30 条候选最多调用两次；成功批次单独提交，后续失败保留剩余内容。模型支持时使用低推理强度，避免推理占满输出预算。无关内容必须显式排除，防止反复审核。
- `npm test`：核心业务、API 与多进程存储测试，网络服务使用隔离替身，不使用真实 Key。
- `npm run build`：类型检查与前后端构建。
- `npm run smoke`：真实读取公共搜索/订阅源，并写入 `reports/live-sources.json`；不调用付费 X 或 AI，不发送邮件。

目录：`web` 页面、`server` API/worker/适配器、`shared` 类型、`tests` 测试、`docs` 需求/方案/研究/验收记录。
