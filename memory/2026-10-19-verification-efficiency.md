# DEBUG REPORT — 提高核实效率

- 日期：2026-10-19
- Status：DONE_WITH_CONCERNS（实现、隔离流程回归及生产构建完成；真实网络与付费模型的核实产出待恢复监控后观察）
- Symptom：用户反馈已核实信息太少，要求提高核实效率。

## Root cause

1. `parseAnalysisOutput` 将同一事件不同材料的所有状态差异统一变成 pending，包括一份官方原文已 confirmed、另一份普通线索 pending 的正常情况。证据合并后确认结论因此丢失。
2. 采集主要用于发现新内容，已有待核实事件没有补证优先级，指标回查还会进一步占用剩余搜索预算。
3. 三次重试用尽的待核实主候选停止进入分析，即便后来有机会取得新证据。
4. 其他待核实候选在正文、关联证据及规则均未变化时仍会反复调用 AI，直至重试耗尽。
5. 引用原文主要沿 X 路径读取，已保存原文未直接复用，非 X 内容的官方外链缺乏同等补证路径。

## Fix

- `server/ai.ts`：同一事件的官方确认与普通 pending 合并时保留确认候选，优先使用已确认材料的摘要与理由；明确 rejected 与其他结论冲突时仍 pending。最终仍经过原有官方/独立可靠原文及时间校验，不因合并直接绕过事实检查。提示词要求结合本批官方证据重新判断旧 pending，并精简不匹配监控的重复引文及解释。
- `server/runner.ts`：有与当前启用监控直接相关的 pending 事件时，预留约 40% 搜索预算补证，并优先安排最多约 40% 主候选名额；视频额外指标回查不得挤占补证预算。无 pending 时延续此前约 80% 发现预算。
- 仍在五天内、与当前监控直接相关的待核实候选可以在三次未解决后继续寻找补证；分析输入以原文、关联证据、作者身份、时间、质量及规则指纹组成。普通轮次中相同证据不再重复调用 AI，新证据或规则变化会使记录失效。手动“重新核实”仍可强制复审，且不新增采集请求。
- 复用同一事件已保存的关联证据及已取得的引用原文；非 X 材料中的官方外链也读取，引用原文与搜索补证正文最多并发读取两份。
- 每日 AI / X 限额、每轮总搜索及材料上限保持原设置，未升级模型或修改用户监控开关。
