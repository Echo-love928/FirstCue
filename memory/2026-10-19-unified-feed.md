# DEBUG REPORT — 统一展示全部信息与扩大采集

- Status：DONE
- 日期：2026-10-19
- 请求：删除已核实／待核实区分与候选待分析提示，增加信息数量。
- Root cause：页面虽有“全部”分类，实际 API 仍只返回完成严格相关性、新颖性和事实流程的事件，已采集原文与搜索摘要必须等 AI 才能展示；互动硬门槛也阻止新线索可见。扩大搜索时还发现重复返回的摘要会覆盖已读取正文。

## Fix

- `server/collected-feed.ts` 读取投影，检查监控匹配、型号作者约束，合并去重，统一返回保存的相关信息。后台状态不再决定原始采集内容的展示；不伪造直接相关审核，不持久化为已确认事件，不进入邮件或飞书队列。
- `server/app.ts` 支持统一视图参数，原有 API 调用与后台通知核验接口兼容。
- `web/src/App.tsx` 删除分类、状态标签、候选提示及审核待办显示，统计改为全部信息／高重要性／覆盖来源／正在监控；所有信息均可复制分享，保留来源详情和用户此前要求的直接相关摘要。
- `server/runner.ts`、`sources.ts`、`parse.ts`、`search.ts` 改为采集后即时保存；单次结果最多 20 条、深入读取最多 10 条、并发最多 3 条；查询补充第二轮变体，不再每轮都强制加月份。保留正文优先，补证不再占用四成发现预算。
- 默认与本机普通搜索设置 10 → 16，AI / X 日限额不变。先用 SQLite backup 完整备份，再以原始设置字符串作乐观条件，只修改搜索上限。
- 无发布时间的原始采集明确显示首次发现时间；已知旧日期不得被重新抓取时间刷新。原始计数保留，未取得的指标不伪造。
